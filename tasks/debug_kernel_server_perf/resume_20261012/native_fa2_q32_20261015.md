# A: native FA2 32-row verify tile

An implemented, opt-in kernel experiment, not a scheduler change or a completed A item.
The stock-FA3 single-split serving pilot continues unchanged on its private tree.

## Kernel and plan contract

The existing native FA2 plan selects64 packed query rows for q4/GQA7, although only28
are useful. This candidate adds a32-row BF16/head128 paged-prefill kernel with two query
warps and two KV warps, versus four query warps and one KV warp for64. It retains the
native nonpersistent work grid, causal masking, PDL dependency handling and split reduction.
Only the new parameter type enables32; other FlashInfer configurations remain unchanged.

The caller must provide the actual maximum request query length. Selection requires an
original64-row plan and maximum packed query extent17–32. Every request then has exactly
one query tile under both geometries. Request/KV-split work lists, merge counts and actual-row
partial-output offsets remain valid; the original64-row workspace allocation is conservative.
The bridge rejects larger query extents, original16-row plans and other tile overrides.
No device-to-host metadata read or allocation is introduced in the launch path.

The new Torch operator has an explicit mutable-output/workspace schema. It is a separate
extension and does not change the currently serving native bridge. Baseline source hashes
match the pod's `fi_fa3_kv_geometry_v2` files exactly.

## Long-context failure and fixed kernel

V1 completes its four initial GPU tests, including profiled32-row/2x2-warp execution, but
stops before timing native32 at one request/64K: the output is nonfinite. The completed8
timings do not constitute a valid performance matrix. A preserved20-run reproduction fails
all20 times, whereas native64 is clean with the same plan, including66 KV chunks of993 tokens.

The new2-query-warp layout exposes shared-union reuse: one query warp can begin writing the
BF16 output while the other still reads cross-KV-warp reduction state from the same union.
V2 adds a CTA barrier after those reads, scoped only to the new32-row kernel. It changes no
attention arithmetic or planner metadata. The same20-run reproduction becomes clean, and
a new32-iteration NaN-poisoned eager/graph regression passes. Racecheck reports zero hazards
even on the failing V1 run, so its zero report is not treated as proof that V1 was race-free.
