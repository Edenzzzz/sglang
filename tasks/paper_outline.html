00Paper outline (10/20)

  • Goal — we need to meet per-tenant SLOs (chat: TTFT + per-token latency; agents: TTFT + TPOT) while maximizing goodput, for mixed chat + long-context agent traffic, with speculative decoding (MTP) on as production runs it — without fixing a prefill / decode split in hardware.
  • Motivation
    • prefill-prioritized chunked prefill — good throughput, but long prefills stall running decodes (agent P99 ITL 1.35 s)
    • mixed chunk — decode rides the prefill step, but every row, 64–256K prefill rows included, runs through one FA2 prefill kernel (~25% more attention time than splitting by role)
    • PD disaggregation — decode isolation, but a few prefill nodes queue every tenant (TTFT 14–31 s at our loads), dilute each prefix across prefill nodes and re-prefill agent turns
    • PD multiplexing — per-phase SM groups, but no CPU-GPU overlap scheduling and one CUDA-graph set per SM group
    • MTP raises decode-node utilization under disaggregation, undercutting "colocation for utilization" unless the colocated schedule is MTP-compatible and efficient — MTP is in scope
  • Design
    • a fused step that runs prefill, decode, draft and verify attention side by side on pre-assigned SMs: FA3 (Hopper TMA / wgmma) for prefill tiles, FA2 for decode / verify tiles, FA2 overlapped beside FA3
    • the 4-mode MTP step: the prefill chunk rides the verify forward, inside the stock scheduler (overlap scheduler on, one CUDA-graph set)
    • why does this help? cheaper per prefill token than mixed chunk, no decode stalls as in prefill-prioritized, and EDF spends each step on deadlines
  • Distributed inference
    • meeting SLOs across nodes requires routing on predicted load, not on a fixed prefill / decode role
    • EDF needs a step-time estimate; the fused step admits a simple one, shared by scheduler and router
    • route each request to the node holding the longest cached prefix that can still meet every SLO; pull the rest from a cluster KV pool (best-effort replication); nodes report their load to the router
  • Evaluation
    • main workload: mixed TraceLab coding agents + ShareGPT chat (standard 32–64K and long 32–250K mixes); multi-node fan-out agents on shared repository prefixes + chat; standalone ShareGPT, math, code and agent / tool traces
    • single node vs prefill-prioritized and mixed chunk (with and without MTP), pdmux as a reference
    • multi-node vs PD disaggregation (with and without MTP on decode); semi-PD if time permits
    • per-tenant SLO attainment and goodput, error bars over repeats, load spikes and mixture shifts, a second model
  • Fault tolerance (if time permits)
    • prefill-node failure propagates to decode nodes under disaggregation; colocated nodes absorb it

—Abstract

LLM serving fleets are disaggregated into prefill and decode nodes so that long prefills never stall decoding. The split is fixed in hardware: it queues requests behind a few prefill nodes, dilutes cached prefixes across them, and leaves decode compute idle — which speculative decoding (MTP) now fills on the disaggregated side. We present AttentionFuse, a colocated serving system in which every node runs prefill and decode together. Its step runs FA3 prefill tiles and FA2 decode / verify tiles on pre-assigned SMs inside sglang's scheduler, with the prefill chunk riding the MTP verify forward (a 4-mode step) and an EDF scheduler that sizes each chunk to deadlines. Across nodes, a cache-first router sends each request to the node holding the most of its prefix that can still meet every SLO, pulling the rest from a cluster KV pool. On mixed coding-agent + chat traffic over 8 H20s, AttentionFuse meets chat SLOs for 91% of requests vs 26% under PD disaggregation and delivers 6× the agent goodput, holding 97–100% agent attainment through a 3× chat spike and a doubled agent load; with a 14B model disaggregation collapses (agent TTFT ~290 s). On one H200 with MTP it raises chat SLO attainment by 72%, agent attainment 15× and throughput 55% over sglang's mixed chunk.

01Introduction

  • Setting / problem
    • production traffic mixes interactive chat (tight TTFT and per-token SLOs) with coding / tool agents whose prompts run 32–250K tokens, share long prefixes across turns and programs, and arrive in bursts
    • MTP speculative decoding is standard and multiplies decode-side work per step
    • goal: meet per-tenant SLOs at the highest request volume per GPU, and adapt to load spikes and mixture shifts without re-provisioning
  • Why existing systems do not meet it
    • prefill-prioritized and mixed-chunk colocation: decodes either stall behind long prefills or pay a slow one-kernel step; neither orders work by deadline
    • PD disaggregation: decode isolation at the cost of prefill queueing, prefix dilution and per-turn re-prefill; the P:D ratio is fixed, so a spike or a mixture shift lands on whichever side is short
    • PD multiplexing: per-phase SM groups, but loses the CPU-GPU overlap scheduler and multiplies CUDA graphs by groups
  • Key insight — the isolation disaggregation buys can be had per step without fixing the split: one fused step runs each attention role on the kernel and SMs it suits, a deadline-driven scheduler decides how much prefill each step carries, and symmetric nodes let the router follow the cache instead of a role table
  • Contributions (§4): (1) SM-pre-assigned FA3 + FA2 split attention; (2) the 4-mode MTP step; (3) EDF scheduling for the fused step with a shared step model; (4) cache-first, SLO-checked multi-node routing over a cluster KV pool
  • Results (§6) — 8 H20s vs PD disaggregation: chat SLO attainment 91% vs 26%, agent goodput 6×, robust to a 3× spike, a 2× agent shift and a 14B model; 1 H200 with MTP: +72% chat attainment, 15× agent attainment, +55% throughput over mixed chunk

02Background

2.1 LLM serving and speculative decoding

  • prefill is compute-bound and parallel; decode reads all of a request's KV per token and is bandwidth-bound
  • MTP / EAGLE3: a draft head proposes tokens, the target verifies them in one forward (acceptance ~2.0–2.1 tokens per verify step on our workloads); a step = draft steps + a verify forward

2.2 Colocated schedules in sglang

  • prefill-prioritized chunked prefill (the default): prefill steps run alone, decodes wait
  • mixed chunk: decode rows ride the prefill step, all through FA2 BatchPrefill
  • PD multiplexing (MuxWise / pdmux): GreenContext SM groups per phase, layer-split prefill; overlap scheduler off; one CUDA-graph set per SM group (5 on H20, 8 on H200)

2.3 PD disaggregation

  • DistServe, Mooncake; sglang prefill / decode roles with mooncake KV transfer; MTP on decode nodes
  • NVIDIA Dynamo: KV-aware router, conditional disaggregation
  • static P:D provisioning: a spike or mixture shift hits whichever side is under-provisioned

2.4 KV-cache-centric scheduling

  • multi-turn and agent workloads reuse long prefixes; cache-aware routing and a cluster KV pool (sglang HiCache + mooncake store) cut TTFT; ThunderAgent documents repeated cache thrashing in agentic serving

03Challenges and motivation

3.1 Attention dominates the mixed step at long context

  • a 743-token chunk at 50K depth is ~28 ms of attention in a 44 ms mixed step (H200); FA3's chunk call already runs at ~540 TFLOP/s — the step is attention-FLOP-bound, so the kernel each row runs on decides the step time

3.2 Mixed chunk pays for its kernel choice

  • decode rows padded into prefill tiles waste only 6.3% / 2.7% / 0.6% of FLOPs at 32K / 64K / 128K
  • running 64–256K prefill rows through FA2 is the cost: attention per 60 steps at 64K, stock 17.7 s vs split 13.3 s (−25%); at 128K the merged batch takes 3.15 ms per call vs 0.83 ms for the split's FA2 calls on mixed steps

3.3 Prefill-prioritized scheduling breaks decode SLOs

  • standard mix: agent P99 ITL 1.35 s, chat TPOT 34.8 ms (vs 20.7 ms for ours without MTP)

3.4 Disaggregation queues, dilutes and re-prefills

  • 8 H20s, fan-out agents: agent TTFT 16–31 s; prefill hit rate falls 0.125 → 0.055 going from 2 to 4 pods while colocation's rises 0.34 → 0.39; re-prefill share 10.3% vs 3.4%

3.5 Speculative decoding is concurrency-limited

  • MTP serves best at sglang's speculative default of 48 running requests for every system (64 and 128 slow every step), so the schedule has to make each step count
  • at that cap the slot, not the GPU, is what new chats wait for: 38% of our chats miss TTFT queued behind it while the running ones decode at 13 ms/token against a 20 ms SLO

04AttentionFuse design

Our main contributions are:

  1. Kernel item 1
    SM-pre-assigned FA3 + FA2 split attention. Each mixed step's work items are dispatched by role: prefill tiles to FA3 on a reserved SM budget (flash-attention's Hopper kernel: paged TMA, wgmma, dynamic scheduler), decode and verify tiles to FA2 (tile classes 64/32/16, auto split-KV) on the remaining SMs, with FA2 launched beside FA3 on a side stream. Both roles are exact against a causal fp32 reference.
  2. Kernel item 2
    The 4-mode MTP step. Prefill chunk, decode, draft and verify in one target forward: the chunk rides the verify forward instead of a separate prefill step, inside sglang's own scheduler — the CPU-GPU overlap scheduler stays on and one CUDA-graph set serves all steps.
  3. Scheduling
    EDF scheduling for the fused step. Deadlines on uncached tokens (base 2 s + 1 s per 5K tokens beyond 4096, doubled above 200K), deadline-driven chunk admission (a small chunk normally, a large one when the backlog would miss a deadline at its pace) and chunk preemption for earlier-deadline arrivals. Decode rows are deadline-ordered too: more requests stay resident than the 48-row MTP graph holds, each step decodes the 48 whose next token is due soonest, and a request is admitted only while every resident row can still meet its TPOT SLO at the measured step time. A closed-form step model of the fused step predicts it at half the error of stock MTP's step and is shared with the router.
  4. Multi-node
    Cache-first, SLO-checked request routing. Symmetric nodes; the router sends each request to the node with the longest cached prefix whose predicted TTFT and ITL — for this request, the earlier-deadline queue ahead of it and the decodes it joins — stay within SLO, else the next. Misses pull the prefix from a cluster KV pool (best-effort replication over a complete RDMA graph). Nodes report decode rows, KV, acceptance and their deadline-ordered prefill queue through sglang's LoadStat channel.

4.1 Problem formulation

  • per-tenant SLOs: chat TTFT 0.5 s and per-request TPOT 20 ms; agents TTFT 10 s and TPOT 80 ms; maximize goodput (output tokens of requests meeting both) per GPU, under bursty, shifting mixtures

4.2 Split attention with SM pre-assignment

  • dispatch: FA3 for prefill-shaped items, FA2 for every verify-width / decode item (FA2 wins every verify-width row in the winner map, 216/216 cells exact)
  • FA3 role = flash-attention's kernel, at parity with sgl-kernel FA3; FA2 runs beside it on the remaining SMs

4.3 The 4-mode MTP step

  • the scheduler attaches the running batch to the prefill step; the spec worker drafts, merges the chunk with the verify rows and splits attention by role; a context / queue gate keeps short prefills on their own step

4.4 EDF scheduling and the step model

  • deadline order decides which prefill a step carries; chunk size follows the deadline backlog
  • deadline-ordered decode rows: a row that has emitted o tokens since it started decoding at t0 is due its next token at t0 + SLO × (o + 1); the K rows due soonest run, the others keep KV and draft state and sit out the step
  • SLO-checked admission: a row with SLO s takes dt / (s × a) of a row slot per step (dt the measured step interval, a the tokens per verify); admit while the resident rows' sum plus the newcomer fits 0.9 × K
  • step model: linear in prefill tokens, prefix attention work, #prefill requests, decode rows, decode KV and the draft / verify terms; fit on serving step traces

4.5 Multi-node routing and the KV pool

  • SLO check: predicted TTFT = EDF queue drain ahead + own prefill (cold-prefill curve, pull-adjusted); ITL from the calibrated decode grid with this request and earlier-deadline requests resident; adaptive ITL SLO = 2.5× the observed TPOT
  • KV pool: mooncake L3 store spanning all nodes; replication happens as a side effect of serving
  • node load: LoadStat extended with decode rows, decode KV, acceptance, deadline-ordered prefill queue and measured decode-step time (ZMQ PUB, change-triggered, 1 s heartbeat)

05Implementation

  • sglang (upstream 3fef129 + ~26 files): split dispatch in the flashinfer backend, the 4-mode step in the EAGLE3 worker, EDF scheduler with deadline chunk and preemption, per-step trace logging
  • FA3 role on flash-attention's kernel (paged TMA, -DNDEBUG, fast math); FA2 from flashinfer 0.7
  • router: aiohttp proxy with the SLO check, cluster prefix index, pull-bandwidth EWMA and LoadStat subscriber
  • KV pool: sglang HiCache with the mooncake store backend over RDMA

07Ablations

  • FA2 overlapped beside FA3 vs back to back: +10% agent throughput, −12% / −16% agent / chat ITL
  • split attention vs one FA2 kernel for the mixed step: −25% attention time at 64K
  • full MTP stack (4-mode step + split + EDF) vs stock MTP: agent attainment 3.0% → 45.8%, chat 34.2% → 58.9%
  • MTP stack minus one component (two repeats): no split kernel −34% agent throughput, attainment agent 11% / chat 37%; no EDF agent attainment 16–20% (vs 47%), chat +0–3 points; no deadline chunk neutral at the standard mix
  • deadline-ordered decode rows + SLO admission on top: chat attainment 58.9% → 63.0%, chat TTFT −21%
  • cache-first SLO-checked routing vs PD roles: re-prefill 10.3% → 3.4%, agent goodput 6×
  • CUDA graphs off: ours −20% throughput, stock MTP −4%; ours still leads (agent +29%, chat attainment 38% vs 23%)

08Related work

  • PD disaggregation: DistServe, Mooncake, NVIDIA Dynamo (conditional disaggregation, KV router)
  • Semi-disaggregation and multiplexing: semi-PD (MPS SM split, restart to resize), DynaServe, MuxWise / sglang pdmux (SM groups per phase) — none fuses attention across phases; pdmux loses the overlap scheduler
  • SLO-aware scheduling: SLOs-Serve (multi-SLO), JITServe (imprecise request information)
  • Agentic serving: ThunderAgent (program-aware, cache thrashing), Crossflow (P/D elasticity), TraceLab (coding-agent workloads)
  • Kernel fusion: POD-Attention, persistent kernels, Taming Dynamism (cross-SM fusion, just-in-time reduction) — we pre-assign SMs per role inside one step
  • Attention-FFN disaggregation (Step-3, MegaScale-Infer): orthogonal, combinable

09Conclusion and limitations

Conclusion. Colocated serving with a fused 4-mode step, EDF and cache-first routing meets per-tenant SLOs at several times the goodput of PD disaggregation, holds them through load spikes and mixture shifts, and stays MTP-compatible — without a fixed prefill / decode split.

Limitations
  • single node vs prefill-prioritized: chat SLO attainment +16.5% (no MTP) / +28% (MTP) at chat 8 req/s; about a quarter of chats decode beside long-context agent prefill chunks and miss a 20 ms TPOT under every schedule
  • per-token decode: disaggregation's decode-only nodes keep 5 ms TPOT vs our 12 ms; the gain is in attainment and goodput, not raw decode speed
  • short-prompt standalone workloads see little gain; the step helps where long-context prefill meets decode
  • MTP is concurrency-limited at 48 running requests for every system
  • open: semi-PD baseline (blocked on a CUDA 12 toolkit install), Blackwell kernels
